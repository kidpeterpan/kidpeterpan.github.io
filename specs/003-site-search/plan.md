# Implementation Plan: Site Search

**Branch**: `003-site-search` | **Date**: 2026-08-08 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/003-site-search/spec.md`

## Summary

Add site-wide search to the static Hugo blog so readers can find posts by
keyword. Approach: run **Pagefind** (v1.5.2, pinned devDependency) over the
built site output after `hugo --minify` in the deploy workflow; serve the
generated index + UI assets from `/pagefind/`; mount the official
`PagefindUI` component inside a native `<dialog>` overlay reachable from the
header on every page, styled with the site's theme tokens. No backend, no
external service, Thai + English matching comes from Pagefind's built-in
language detection.

## Technical Context

**Language/Version**: Go templates (Hugo 0.164+), vanilla JavaScript, Tailwind CSS v4

**Primary Dependencies**: `pagefind` v1.5.2 (devDependency, build-time only); Hugo built-ins; no new runtime libraries

**Storage**: N/A (static search index generated into `public/pagefind/`)

**Testing**: No automated test suite per repo convention — manual verification via quickstart.md + `hugo --minify` build gate

**Target Platform**: Modern browsers (all browsers supporting `<dialog>`); GitHub Pages static hosting

**Project Type**: Static blog (Hugo + GitHub Pages)

**Performance Goals**: Results visible within 1 second of a few typed characters on a typical connection (SC-002)

**Constraints**: No backend; no third-party query traffic; index rebuilt every deploy; must support Thai text; must match "Plus Ultra Paper" theme in light + dark mode; keyboard accessible

**Scale/Scope**: Small personal blog (~20 posts); single site, no multi-language variants beyond auto-detected content language
